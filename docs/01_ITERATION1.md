# Итерация 1: экзамен, «Ткань-0» и первые органы

> Всё считается в облачном контейнере (4 CPU, 15 ГБ ОЗУ, без GPU). Компьютер пользователя не используется.

## Экзамен

Каждая задача существует в двух версиях — русской и английской — с одинаковым содержанием.

| Домен | Что проверяет | Уровни 1 → 5 |
|---|---|---|
| math | арифметика | 1-значное сложение → 2-значное × 2-значное |
| word | текстовые задачи | 1 действие → 3 действия с умножением |
| order | логика (транзитивность) | 2 человека → 6 человек, факты перемешаны |
| seq | продолжить ряд | арифметическая прогрессия → ряд Фибоначчи |
| code | написать функцию на Python | `x * k` → цикл с условием; **проверка запуском на тестах** |
| trace | что выведет программа | одно присваивание → цикл с условием; истина получена исполнением |

Как устроено разбиение:
- Тест и обучение разделены по содержанию задачи (crc32 ключа без языка). Утечка проверена: 0 совпадений на 20 000 обучающих задач.
- **Уровень 5 в обучении не встречается никогда**: он проверяет, обобщает ли модель на более трудное.

Русские тексты задач грамматически согласованы: «была 21 конфета», «отдала 1 конфету», «был 1 мяч».

## «Ткань-0»: устройство

```
байты → [энкодер: 2 причинных свёрточных блока]
      → [роутер: граница там, где соседние байты «неожиданно» различаются]   ← модель решает сама
      → чанки (~4 байта) → [прелюдия] → [общий блок × r] → [кода]           ← r — «время на мысль»
      → [сглаживание + разжатие] → [декодер: 2 блока] → следующий байт
```

- Нарезку никто не задаёт: есть только целевое *среднее* сжатие (ratio-loss).
- Число циклов при обучении случайное (1…6), градиент течёт через последние 2 цикла.
- При работе r можно задать любым.
- 6.5M параметров. Это масштаб для проверки органов на CPU, а не для эрудиции.

## Эксперименты

- **A** — нарезку модель выучивает сама.
- **B** — фиксированная нарезка по 4 байта; всё остальное как в A. Время обучения одинаковое.
- **Qwen3-0.6B** — эталон на том же экзамене (3 примера формата в запросе).

Результаты — ниже.

## Результаты итерации 1 (честно)

### Язык: бит на байт на отложенной Википедии и коде (меньше — лучше)

| Модель | Обучение | Данных | wiki RU | wiki EN | код | байт/кусок RU / EN / код |
|---|---|---|---|---|---|---|
| A: нарезку выбирает сама | 110 мин, 2 CPU | 21.0 МБ | 1.555 | 2.451 | 2.157 | 3.2 / 4.8 / 3.6 |
| B: нарезка по 4 байта | 110 мин, 2 CPU | 24.5 МБ | **1.531** | **2.414** | **2.101** | 4 / 4 / 4 |

На одинаковом шаге обучения A и B идут вровень, на коде A даже чуть лучше.
- Шаг 1000: A — 1.84 / 2.78 / 2.40, B — 1.81 / 2.74 / 2.41.
- Шаг 2000: A — 1.61 / 2.52 / 2.20, B — 1.61 / 2.52 / 2.23.

Но собственная нарезка стоит ~16% вычислений, поэтому за то же время B увидел больше данных и в итоге чуть лучше.

**H1 на этом масштабе не подтверждена.** Самообучаемая нарезка не дала выигрыша на 6.5M параметров и 21 МБ данных. В H-Net выигрыш появлялся от ~1B параметров. Есть и наблюдение в пользу идеи: модель сама даёт русскому и коду больше кусков на символ, то есть больше вычислений там, где ей труднее. При этом для русского она пока режет посреди двухбайтовых букв — осмысленных единиц ещё не нашла:

```
EN: The qu|ick br|ow|n fox| jumps| ove|r| the la|z|y| do|g near the riv|e|r bank|.
```

### Экзамен (r = 6)

| Модель | RU | EN | MGSM ru/en |
|---|---|---|---|
| A | 2.9% | 4.0% | 0 / 0 |
| B | 3.6% | 4.0% | 0 / 0 |
| **Qwen3-0.6B** (эталон, 3-shot) | **69.0%** | **60.6%** | — |

Обе «Ткани» провалили экзамен.

Разбор показал: модели выучили формат ответа, но не смотрят в условие. На любую задачу «напиши функцию» они пишут `return x * x`, на арифметику отвечают «частыми» числами.

Это не ошибка в коде. Контрольный прогон — 8 минут только на задачах math+order — дал 80% на сложении однозначных чисел (RU и EN). Причина в нехватке практики: в смеси с Википедией на каждую ячейку экзамена пришлось всего ~3 тыс. примеров.

### Циклы мысли

**H2 в этой постановке провалилась.** Качество не зависит от r *вообще*: bpb при r=1 и r=12 совпадает до 6-го знака, экзамен тоже. Модель научилась игнорировать повторные проходы ядра.

Вероятная причина в обучении. r выбиралось из U{1..6}, начальное состояние было нулевым, и модели выгодно решать всё за один проход.

Исправление в итерации 2: r ∈ {2..8}, случайное начальное состояние мысли (как в Huginn), чтобы ядро училось сходиться.

### Эталон Qwen3-0.6B по доменам

| домен | RU | EN | слабое место |
|---|---|---|---|
| math | 98% | 100% | — |
| word | 68% | 62% | уровень 3 (a + b − c) и 5 |
| order | 66% | 34% | иногда отвечает именем из примеров, которого нет в вопросе |
| seq | 53% | 47% | уровни 4–5 (растущие разности, Фибоначчи) |
| code | 94% | 90% | — |
| trace | 42% | 40% | циклы (уровни 4–5) |

ECE = 0.053.

### Выводы для итерации 2

1. Организмы в 6.5M параметров на CPU — инструмент проверки органов, а не собеседник. Смесь сдвигаем к задачам (90%), язык придёт через пересадку знаний.
2. Чиним рекурсию: r ≥ 2 и случайное начальное состояние; проверяем, растёт ли качество с r.
3. Включаем «руки»: учитель показывает решение через Python (прогон C) — проверяем, сколько это даёт маленькой модели.
4. Пересадка знаний (`tkan/transplant.py`): «глаз» и «голос» вокруг ядра Qwen3-0.6B — путь к настоящему диалогу.
