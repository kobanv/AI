### Главная находка: привычка верная, а «зрение» неточное

C на каждую задачу пишет программу и правильно читает результат исполнения. Но числа из условия она переписывает с ошибками:

```
Сколько будет 23 + 97?    → <py>print(32 + 97)</py><out>129</out> 129
Сколько будет 334 - 253?  → <py>print(343 - 351)</py><out>105</out> 105
Сколько будет 61 * 18?    → <py>print(61 * 9)</py>   (уровень 5 не тренировался: «тянет» шаблон 2×1)
x = 2; y = x * 2 - 7      → <py>x = 4\ny = x * 9 - 3 ...</py>
```

Причина в архитектуре. Байтовый декодер видит лишь ~22 соседних байта, а до условия дотягивается только через сжатые чанки, где точные цифры теряются.

**Исправление (модель D):** слой внимания по байтам в декодере — окно 256 байт, «точный взгляд» назад.

### Рекурсия: снова не используется

bpb и экзамен R/C одинаковы при r = 2…16 (до 5-го знака). Случайное начальное состояние лишь научило модель игнорировать мысль: шум проще всего не замечать.

**Исправление (модель D):** мысль подмешивается сложением (`s ← s + e`), а не через адаптер. Обойти её так нельзя.

## Цикл саморазвития (`tkan/selfimprove.py`)

В цикле **нет ответов учителя**:
- **мир** ставит задачи и говорит «верно/неверно»;
- **модель** сама:
  - строит карту навыков;
  - выбирает фокус: «почти получается», «растёт», «следующий шаг после освоенного»;
  - пробует решить, жадно и с температурой;
  - учится во «сне» только на решениях, прошедших проверку;
  - ведёт дневник.

Экзаменационные задачи для практики закрыты. Навык code/5 закрыт целиком: все его задачи ушли на экзамен.

Запущен на модели C, 8 раундов. Результаты — ниже, когда будут готовы.

## Модель D: «точный взгляд» решает главную проблему

D = C + слой внимания по байтам в декодере (окно 256) + мысль, подмешиваемая сложением. Обучение то же: 75 минут на 2 CPU, 6.9M параметров.

По пути нашлась ошибка в «руках». Если метка `</py>` разрывалась между двумя порциями генерации, программа не запускалась, и модель выдумывала результат сама (0% на трёхзначной арифметике). Исправлено, добавлен регрессионный тест.

| домен | D (RU / EN) | Qwen3-0.6B (RU / EN) |
|---|---|---|
| math | 80% / 80% (ур. 1–4: 100%) | 98% / 100% |
| word | **82% / 80%** | 68% / 62% |
| trace | **82% / 82%** | 42% / 40% |
| code | 68% / 58% | 94% / 90% |
| seq | 21% / 16% | 53% / 47% |
| order | 12% / 14% | 66% / 34% |
| **итого** | **57.7% / 55.8%** | 69.0% / 60.6% |

**Честно о сравнении.** D обучалась на задачах этого вида: конкретные экзаменационные задачи она не видела, но шаблоны знает. Qwen — общая модель и видит лишь 3 примера. Поэтому это доказательство того, что органы работают, а не «равенство по уму».

Настоящая граница:
- **уровень 5** (не было в обучении) — 0–10%;
- **логика упорядочивания и ряды** — Python тут не помогает, нужно рассуждать.

**Урок архитектуры:** иерархической байтовой модели обязательно нужно точное внимание по байтам. Без него сжатые чанки теряют цифры, и модель не может их дословно скопировать. Итог: 17.5% → 57%.

**Рекурсия:** по-прежнему не используется (bpb меняется в 5-м знаке). H2 на этом масштабе не подтверждена — переносим проверку на GPU (Colab), где можно дать глубокое обучение по шагам мысли.

## Цикл саморазвития: два урока

**Версия 1** — без повторения: катастрофическое забывание. Средняя компетентность упала с 35.6% до 20.1% после первого же сна на 33 своих решениях.

**Версия 2** — повторение + «не навреди» (откат, если после сна стало хуже):
- самопроверка росла: 37.5% → 39.2 → 39.7 → 39.7 → 41.4 → 41.8 → 42.2%, все 6 раундов приняты;
- **а экзамен упал:** 18.2% → 12.4% (RU), 16.8% → 9.5% (EN).

Модель «обманула себя». Решения с самопроверки шли в сон на повторение, то есть она училась ровно на тех задачах, по которым себя проверяла. Плюс практика шла только на знакомых задачах. Это закон Гудхарта: показатель, ставший целью, перестаёт измерять.

**Версия 3** (запущена на D):
- самопроверка — только на невиданных задачах, на которых модель никогда не учится;
- повторение — на её собственных проверенных решениях обычных обучающих задач;
- сон мягче.
